# AI_USAGE — LAB 06

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง — ถ้าอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

## ครั้งที่ 1

**ถามอะไร**

ถามวิธีทดสอบ API เพิ่มคำร้องใหม่ด้วย `POST` ใน Postman และวิธีตรวจสอบว่า API ทำงานถูกต้อง รวมถึงการบันทึก `status ที่ได้จริง`

**AI ตอบว่าอย่างไร (สรุปสั้น)**

AI อธิบายการตั้งค่า Postman เป็น `POST` และส่งข้อมูลแบบ `raw JSON` จากนั้นกด Send และตรวจ HTTP Status Code เช่น `201` เมื่อสร้างข้อมูลสำเร็จ นอกจากนี้อธิบายว่า `status ที่ได้จริง` ต้องใส่ค่าที่ Postman แสดงจริง เช่น `200`, `201`, `400` หรือ `404`

**ใช้ส่วนไหน / แก้เองตรงไหน**

ใช้คำอธิบายในการทดสอบ API ผ่าน Postman และนำไปกรอกผลการทดสอบใน `API_TEST.md` ส่วน URL และข้อมูล JSON ที่ใช้ทดสอบตรวจสอบและปรับให้ตรงกับ API ของโปรเจกต์เอง

## ครั้งที่ 2

**ถามอะไร**

ถามวิธีทำ `PUT /api/requests/:id` เพื่อเปลี่ยนสถานะคำร้อง โดยต้องรองรับสถานะ `pending`, `in-progress` และ `completed` และต้องตอบ `400` เมื่อส่งสถานะที่ไม่ถูกต้อง และ `404` เมื่อไม่พบคำร้อง

**AI ตอบว่าอย่างไร (สรุปสั้น)**

AI อธิบายว่า Route สามารถใช้

`router.put('/:id', controller.updateRequestStatus);`

และให้ Controller ตรวจสอบค่า `status` กับรายการค่าที่อนุญาต จากนั้นเรียก Service เพื่อเปลี่ยนข้อมูล โดยแบ่งผลลัพธ์เป็น `200` เมื่อสำเร็จ, `400` เมื่อ status ไม่ถูกต้อง และ `404` เมื่อไม่พบคำร้อง

**ใช้ส่วนไหน / แก้เองตรงไหน**

นำแนวทางการตรวจสอบ `status` และการแบ่ง HTTP Status Code ไปปรับใช้กับโค้ดของโปรเจกต์เอง เดิมใช้ `validateRequest` กับ PUT แล้วพบว่าบังคับให้ส่งข้อมูลทุก field จึงปรับให้ PUT รับเฉพาะ `status` ตามที่โจทย์กำหนด และตรวจสอบการทำงานผ่าน Postman

## สรุป

- **ส่วนที่เขียนเองทั้งหมด:**  
  โครงสร้างโปรเจกต์ Route เดิม การเชื่อมต่อ API และการทดสอบ API ใน Postman รวมถึงการปรับโค้ดให้ตรงกับโครงสร้างของโปรเจกต์

- **ส่วนที่ AI ช่วย:**  
  อธิบายหลักการทำงานของ Route, Controller, Service, การใช้ HTTP Status Code และแนวทางตรวจสอบ `status` สำหรับ PUT รวมถึงช่วยวิเคราะห์ Error ที่เกิดขึ้นระหว่างทดสอบ

- **ส่วนที่ยังไม่มั่นใจ:**  
  การเชื่อมต่อระหว่าง Controller กับ Service และรูปแบบ `import/export` ของ `requestService` รวมถึงรายละเอียดการจัดการข้อมูลภายใน Service
